# Wayback Auto Archiver

## 概要

PC の Chrome でアクセスしたページの URL を、Wayback Machine に自動送信する個人用 Chrome 拡張（Manifest V3）です。安全のための除外ルールがあり、すべてのページが保存されるわけではありません。Chrome で開いたページだけが対象です。

## CLI での入れ方

Mac で Git と Python 3 が必要です。Git がなければ `xcode-select --install` を実行してください。

```bash
curl -fsSL https://raw.githubusercontent.com/kandotrun/auto-wayback-machine/main/install.sh | bash
```

リポジトリを `~/auto-wayback-machine` に取得し、PNG アイコンを生成して、読み込むフォルダのパスをクリップボードへコピーし、Chrome の拡張機能ページを開きます。初回は次の操作をしてください。

1. `chrome://extensions/` で「デベロッパーモード」を ON にする。
2. 「パッケージ化されていない拡張機能を読み込む」を押す。
3. コピーしたパスを貼り付け、**`~/auto-wayback-machine/extension`** を選ぶ。

更新時は同じコマンドを再実行し、拡張機能ページで ↻ を押してください。`AUTO_WAYBACK_DIR` で取得先を指定できます。

手動で取得した場合は、リポジトリのルートで次を実行し、`extension/` を読み込みます。Node.js やビルドはインストールに不要です。

```bash
python3 scripts/generate_icons.py
```

旧版でリポジトリのルートを読み込んでいる場合は、更新後の読み込み先が `extension/` に変わります。切り替え前に旧版の設定・履歴を確認してください。Chrome が別の拡張として扱う場合、既存のローカルデータは自動移行されません。

## 仕組み

- メインフレームの表示完了と SPA の履歴変更を検知し、URL のフラグメントと追跡用クエリを除去して除外判定する。
- 同じ URL の保存済み記録（初期値 24 時間）とキュー内の重複を確認して、キューに追加する。
- 初期値 8 秒間隔で `https://web.archive.org/save/<URL>` に GET を送る。ログイン用 Cookie は送らない。
- Save Page Now のデフォルト動作で、ページ本体と表示に必要な埋め込みリソース（画像・CSS・JavaScript）を保存対象とする。
- Wayback 側の `capture_outlinks`、`capture_screenshot`、`capture_all` は指定しない。リンク先保存を ON にした場合だけ、拡張自身がユーザーの開いたページからリンクを収集し、同じ安全フィルタ・重複排除を通してキューの末尾へ追加する。
- AI チェックを ON にした場合は、送信直前にルールを再確認してから URL とページタイトルだけを Ollama へ渡す。`safe` の場合だけ Wayback に送る。`unsafe` / `uncertain` は保留にする。
- 429 / 503 では項目を残し、5 分後の再試行アラームと永続化した待機期限を設定する。AI 用アラームや新規訪問でこの待機を短縮しない。それ以外の送信失敗は 3 回で失敗として記録する。
- 設定・キュー・重複記録・履歴・統計は `chrome.storage.local` に保存する。起動時やアラームでキュー処理を再開する。
- 履歴は最大 200 件、重複記録は直近 30 日以内の最大 5,000 件を保持する。

ポップアップで自動保存の ON/OFF、統計、最近の送信履歴を確認できます。「このページを今すぐ保存」は重複期間を無視してキューに追加しますが、安全フィルタと、有効な場合の AI チェックは適用します。自動保存が OFF の間はキュー処理も停止します。

## 設定

ポップアップの「設定（除外リストなど）」から変更します。

| 設定 | 初期値・意味 |
| --- | --- |
| 自動保存 | ON |
| 同じ URL を再保存しない期間 | 24 時間（0 で保存済み記録による重複排除を無効化） |
| 保存リクエストの最小間隔 | 8 秒（保存可能範囲 4〜120 秒） |
| トラッキングパラメータの除去 | ON。`utm_*`、`fbclid`、`gclid` などを除去 |
| センシティブなクエリの除外 | ON。`token`、`session`、`password`、`code` などのキーを除外 |
| 除外ホスト | `localhost`、`127.0.0.1`、`web.archive.org`、`archive.org`、`accounts.google.com`、`mail.google.com` |
| 除外パターン | 空。URL に含まれる文字列を大文字・小文字を区別して照合 |
| リンク先保存（`captureOutlinks`） | OFF（オプトイン） |
| 同一ホスト制限（`outlinksSameDomainOnly`） | ON。リンク元と同一ホストか、その配下のサブドメインだけ |
| ページごとのリンク上限（`outlinksMaxPerPage`） | 30 件。0〜500 件。除外・重複判定を通過した順に数える |
| AI チェック（`aiCheckEnabled`） | OFF（オプトイン）。手動保存にも適用 |
| AI エンドポイント（`aiCheckEndpoint`） | `http://127.0.0.1:11434` |
| AI モデル（`aiCheckModel`） | `qwen3.8:27b-mlx` |

除外ホストはサブドメインにも適用します。`example.com` と `*.example.com` はどちらも本体とサブドメインを除外します。「履歴と重複記録をクリア」はキューと統計もクリアします。

### リンク先の保存

HTTP/HTTPS ページのトップフレームに `document_idle` で実行する content script を使います。background がリンク元に対する保存許可と設定を確認してから、`a[href]` の URL を収集します。本文・リンクテキストは送信しません。リンク元自体が除外対象なら、リンク一覧を収集しません。

リンク先もプライベート IP、認証情報入り URL、センシティブなクエリ、除外ホスト・パターン、保存済み期間・キュー内重複を同じルールで判定します。同一ホスト制限が ON なら、例えば `example.com` から `sub.example.com` は許可しますが、`sub.example.com` から親の `example.com` や兄弟ホストは許可しません。

収集はそのページの読み込み後に 1 回だけです。保存しただけのリンク先へ拡張がアクセスして、さらにリンクをたどることはありません。ユーザーがそのリンク先を Chrome で開いた場合は、通常の訪問ページとして対象になります。Wayback の SPN2 `capture_outlinks` は使いません。

### AI チェックの接続と保留

Ollama の [`POST /api/chat`](https://docs.ollama.com/api/chat) を使い、`stream: false` で判定します。MLX 系モデルは structured output に HTTP 501 を返すことがあるため、`format` は指定しません。応答の `content` から素の JSON、コードフェンス内の JSON、前後に説明のある最初の JSON オブジェクトを読み取ります。形式や判定内容が不正・曖昧なら送信しません。ベース URL または `/api/chat` までの URL を指定できます。OpenAI 互換の chat completions や API キー認証には対応していません。クラウドへ接続する場合も、Ollama のリクエスト・レスポンス形式に対応した接続先が必要です。

基本の接続先は、Chrome と同じ Mac 上の **`http://127.0.0.1:11434`** です。Tailscale Serve のホスト名経由では Ollama の Origin チェックで POST が 403 になる実測があるため、基本手順ではそのホスト名を使いません。

設定を ON にして保存すると、接続先への Chrome のアクセス権限を要求します。拒否した場合は設定を保存しません。ローカルの Ollama を起動し、指定モデルを用意してから使ってください。Mac にモデルが存在することや、判定精度はインストーラでは検証しません。

Ollama が拡張からのリクエストを拒否する場合は、`chrome://extensions/` に表示される拡張 ID のオリジンを `OLLAMA_ORIGINS` に許可します。Mac の Ollama アプリなら、ID を置き換えて次を実行し、Ollama を再起動します。設定の詳細は [Ollama FAQ](https://docs.ollama.com/faq#how-can-i-allow-additional-web-origins-to-access-ollama) を参照してください。

```bash
launchctl setenv OLLAMA_ORIGINS "chrome-extension://ここを拡張IDに置換"
```

判定には URL と取得できたページタイトルだけを渡します。本文・Cookie・リンクテキスト・送信履歴は渡しません。まだ開いていないリンク先や旧キューの項目など、タイトルが分からない場合は空文字です。判定用にリンク先の本文やタイトルを取得することはありません。

認証情報、個人情報、非公開文書・ワークスペース、金融・医療、社内システムの観点で `safe` / `unsafe` / `uncertain` と固定カテゴリを返させます。`unsafe` と `uncertain` は即時保留です。接続失敗、HTTP エラー、不正な JSON、未知の判定、タイムアウト（20 秒）では送信せず、1 分後に再試行します。合計 3 回で保留にし、再試行待ちの項目は後続のキュー処理を妨げません。試行回数と待機期限はキューに永続化し、ワーカー停止中の試行も回数に含めます。

保留にした項目は実行キューから外し、ログに固定ステータス・カテゴリ・時刻だけを残します。URL・タイトル・モデルの説明文は保留ログに残しません。スキップ件数に含め、ポップアップの「最近の処理」に表示します。保留一覧として URL を保存したり、後で自動再送したりする機能はありません。再確認したい場合は、ページを再表示するか「今すぐ保存」を押してください。手動でもルールや AI を迂回しません。AI チェックを OFF にした場合は、残っているキューを従来のルールだけで処理します。

## プライバシーと安全上の注意

URL は外部サービスの Internet Archive に送られ、保存結果が公開される可能性があります。一度保存されたものは原則として取り消せません。銀行や Web メールなど、URL 自体を知られたくないサイトは除外ホストに追加してください。

ローカル／プライベートホスト（localhost、`.local`、127.*、10.*、192.168.*、172.16〜31.*）と IPv6 ホスト、認証情報入り URL は設定にかかわらず送りません。センシティブなクエリの除外は既知のキーに対する判定であり、すべての秘密情報を検出できるものではありません。URL のパスや独自のクエリに秘密が入るサイトは、ホストやパターンで除外してください。手動保存にも同じ安全判定を適用します。

AI の接続先にクラウド LLM や外部プロキシを指定すると、Wayback へ送らないと判定された URL も含め、URL とページタイトル自体がその接続先へ出ます。接続先の保存・利用方針を確認してください。ローカルサーバーでも、選択したモデルやプロキシがクラウドへ転送する構成なら外部送信になります。AI チェックは既定では OFF で、ON にしてもすべての機密情報を検出できる保証はありません。

## 制限

- Chrome 137 以降の通常版 Google Chrome では `--load-extension` が使えないため、拡張機能ページで手動読み込みが必要です。
- Wayback のクローラはあなたのログイン状態を持ちません。ログインが必要なページは、公開側やログイン画面が保存されるため、見た画面そのものの記録にはなりません。
- JavaScript で描画するページは保存が不完全になることがあります。サイトや Wayback 側の制限で保存できない場合もあります。
- Wayback のデフォルト保存対象はページ本体と埋め込みリソースです。リンク先は拡張のオプションが ON の場合だけ別の保存リクエストになります。SPN2 にリンク先収集を委ねず、スクリーンショット保存とエラーページを含める保存も有効にしていません。
- リンク収集は読み込み後の DOM にある `a[href]` から 1 段だけです。後から追加されたリンクや、SPA 内だけの遷移後のリンク一覧は再収集しません。iframe 内、クリック用 JavaScript やフォームの遷移先も収集しません。
- AI は URL と取得できたタイトルだけを判定するため、本文中の秘密情報は判定できません。ページタイトル等による判定誘導を防ぐプロンプトを使いますが、誤判定を完全には防げません。
- AI が遅い場合は 20 秒で判定不能として扱います。モデルの初回ロードなどで継続して遅い場合は、保留になることがあります。
- 「送信済み」（`submitted`）は、送信リクエストの HTTP 応答が成功扱い（200〜399）だった件数です。`/save/status` のポーリングによる Wayback 側ジョブの完了確認は行っていません。保存の完了や、ページ本体・埋め込みリソースがすべて保存されたことを保証するものではありません。
- MV3 のサービスワーカーは Chrome に停止されるため、送信間隔や再試行時刻は厳密な実行保証ではありません。

## 開発とテスト

Node.js 22 以降と Python 3 を使います。依存パッケージの追加や `npm install`、ビルドは不要です。

```bash
python3 scripts/generate_icons.py
npm run check
npm test
python3 scripts/check_icons.py
```

`check` は JavaScript の `node --check`、シェル構文、バージョンの整合、manifest・HTML・ES module の参照先を確認します。アイコン生成を先に実行してください。`test` は Node 標準テストランナーで URL・除外・重複・履歴・リンク選別・AI 判定・サービスワーカーの挙動を検証します。GitHub Actions でも push / pull request 時に実行します。

Chrome での確認手順と、今回の整理で維持する仕様は [検証メモ](docs/verification.md) を参照してください。生成 PNG は Git に追加しません。
