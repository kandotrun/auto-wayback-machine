# 既存仕様と追加機能の検証

## 自動検証

- 最初の WIP で初版の URL 正規化・除外判定に対する基準テストを作り、分割後も同じテストを実行する。
- URL の許可スキーム、認証情報、追跡クエリ除去、ホスト・パターン・センシティブクエリ判定、24 時間境界、キュー内重複、履歴の保持期間と上限を検証する。
- Chrome API と fetch をスタブ化し、サービスワーカーのイベント登録、保存処理、永続キュー再開、429/503、手動保存を確認する。外部への保存要求は送信しない。
- 既存の初期設定と URL 判定を維持し、リンク先保存は OFF、AI は auto を既定とする。content_scripts の HTTP/HTTPS 読み取り、ローカル Ollama の必須ホスト権限と、差し替え AI 接続先の optional_host_permissions は今回の追加権限。
- リンク元許可前の DOM 収集禁止、同一ホストと配下サブドメイン、除外・重複後の上限、メッセージのトップフレーム・リンク元 URL 検証をテストする。
- MLX の format なしリクエスト、JSON・コードフェンス・説明付き JSON の抽出と判定の厳密解釈、safe だけ送信、unsafe/uncertain の保留、ネットワーク・HTTP・JSON・タイムアウトの fail closed、合計 3 回の試行上限、後続キューの進行、手動保存への適用をテストする。
- AI に渡す user データは URL とタイトルだけであること、保留ログに URL・タイトル・自由文の理由が残らないことをテストする。
- ローカルの合成 HTTP サーバーで Ollama /api/chat 契約のスモークテストを行う。実モデルの品質や実 Chrome の通信を証明するものではない。

## Chrome での手動確認

この手順は実ブラウザでの確認用。自動テストの成功だけでは、Chrome へのロードや実際の Wayback 保存の成功を保証しない。

1. アイコン生成後、chrome://extensions で extension/ を読み込み、サービスワーカーに import エラーがないことを確認する。
2. 公開してよい URL を開き、ポップアップのキュー・送信済み件数・履歴リンクを確認する。
3. 同じ URL を再表示して 24 時間以内に追加されないこと、追跡クエリやフラグメントの違いでも重複しないことを確認する。
4. 自動保存を OFF にしてキューが停止すること、ON に戻して処理されることを確認する。
5. 設定で除外ホスト・パターン、間隔、重複期間、追跡除去・クエリ除外のスイッチを変更し、再表示して保持されることを確認する。
6. localhost・プライベート IP・認証情報入り URL・token 付き URL で送信されないことを確認する。公開してよい URL の手動保存は重複期間を無視し、除外対象の手動保存は理由を表示する。
7. キューが残っている状態で Chrome を再起動し、処理を再開することを確認する。
8. 「履歴と重複記録をクリア」で履歴・重複記録・キュー・統計が消えることを確認する。

## 整理の判断

拡張だけを extension/ にまとめ、Chrome へ開発用ファイルを渡さない構成にする。
install.sh は既存の curl URL を維持するためルートに残す。
README は利用者の入口としてルートに残し、検証手順だけ docs/ に分ける。
画面は小さいため popup と options をさらにフォルダ分割せず、共通処理だけ shared/ にまとめる。
バージョンはこの初版 PR 内では 1.0.0 を維持し、package.json との一致を機械検証する。

既存の Wayback 送信間隔・5 分バックオフと、サービスワーカー内のタイマーを維持する。AI 用アラームがバックオフを短縮しないよう、backoffUntil を永続化して送信前に確認する。
追加された AI 通信中に enqueue や clear が重なるため、worker の read/modify/write を直列化し、送信直前に現在の設定・項目・除外ルールを再確認する。
AI 判定は Wayback 再試行ごとにも実行し、安全判定をキャッシュしない。判定不能の試行回数・待機期限は fetch 前に永続化する。
配置変更は Chrome の拡張 ID・ローカルストレージの引き継ぎに影響する可能性があるため、README に切り替え時の注意を記載する。


## リンク先保存の手動確認

1. 初期状態の captureOutlinks が OFF、同一ホスト制限が ON、上限が 30 であることを確認する。
2. 公開してよいテストページに、本体・サブドメイン・外部ホスト・重複・追跡クエリ・token 付きリンクを置く。ON にして再ロードし、条件を通ったリンクだけがキュー末尾に入ることを確認する。
3. 同一ホスト制限の OFF、上限 0 / 2 / 30 を確認する。上限は除外・重複を取り除いた後の件数であることを確認する。
4. リンク元を除外ホスト・パターンに追加し、再ロードしてリンク先を収集しないことを確認する。
5. 保存されたリンク先を Chrome で開かない限り、さらに先のリンクは追加されないことを確認する。
6. SPN2 capture_outlinks / capture_screenshot / capture_all が送信要求に追加されないことを確認する。

## AI チェックの手動確認

1. 設定の初期値が auto / http://127.0.0.1:11434 / qwen3.8:27b-mlx であることを確認する。off なら疎通も判定も行わず、auto は未接続時に通常送信、on は未接続でも送信しないことを確認する。
2. 同一 Mac 上の http://127.0.0.1:11434 を使う。Tailscale Serve のホスト名経由は Origin 判定で POST が 403 になる実測があるため、基本確認では使わない。別の接続先を選んで auto/on で保存し、接続先への権限要求を確認する。拒否時は保存されないことを確認する。Ollama の拡張オリジン許可は README の手順を使う。
3. リクエストに format がないことを確認する。素の JSON、コードフェンス付き JSON、説明に囲まれた JSON を返す場合を含め、合成 URL とタイトルで safe / unsafe / uncertain を返すテストサーバーを使い、safe だけが Wayback へ送信されることを確認する。実モデルの精度確認は別に行う。
4. 送信データに URL とタイトル以外のページ情報・Cookie がないことを確認する。リンク先のタイトルが不明な場合は空文字であり、本文を取りに行かないことを確認する。
5. 手動保存も同じ AI 判定にかかること、ルールで除外される URL は AI にも渡らないことを確認する。
6. on モードで接続停止・不正 JSON・タイムアウト（60 秒）にし、後続項目が処理され、対象は 1 分待ちで合計 3 回を上限に保留となることを確認する。待機中に Chrome を再起動し、回数と期限が残ることも確認する。
7. 保留ログが固定ステータス・カテゴリ・時刻だけで、URL・タイトル・理由を含まないことを確認する。保留後の自動再送はなく、再表示・手動保存で再判定できることを確認する。
8. AI 通信中にキューをクリア、除外ルールを追加、自動保存を OFF にし、該当 URL が送信されないことを確認する。
9. auto では疎通結果が 30 秒キャッシュされ、未接続時の確認が 1.5 秒以内で終わることを確認する。疎通確認が HTTP 403 / 404 / 503 の場合は AI をスキップして通常送信すること、疎通確認が成功した後の判定失敗は再試行・保留になることを確認する。on では HTTP 403 でも通常送信せず、合計 3 回で保留になることを確認する。
10. 外部 LLM 接続では URL とタイトルが外部へ出るため、確認用の合成データだけを使う。

## 実施範囲

Node の単体・スタブ結合テストと、ローカルの合成 HTTP サーバーを使った通信契約テストを実施。
実 Chrome への拡張ロード、Chrome の権限ダイアログ、実 Ollama モデルの存在・精度・速度、実 Wayback 保存は未検証。


## Ollama セットアップの検証

- 一時 Git fixture を実 clone し、アイコンを実生成する。Ollama・公式インストーラ・curl・macOS 起動操作だけをスタブにする。
- 未導入なら公式インストーラを 1 回だけ実行、導入済みなら再インストールしないこと、app 起動・tags 待機・pull の順序、既定モデルと AWM_JUDGE_MODEL の上書きを確認する。
- 許可値変更時の稼働中アプリ再起動、設定済みでも古い環境で Origin 403 なら再起動、拡張 Origin 付き API 回復後の pull、許可済みなら不要な再起動をしないこと、終了待ち上限をスタブで確認する。実機でもセットアップ前から起動した Ollama で再起動理由の出力と拡張からの 403 解消を確認する。
- GUI ドメインの sh.brew.ollama / homebrew.mxcl.ollama の検出、kickstart による再起動と Origin 回復、正常稼働時の再起動省略をスタブで確認する。kickstart 失敗・再起動後の Origin 回復待ち上限では警告とし、Ollama.app や別サーバーの起動・pull を行わないことを確認する。
- AWM_SKIP_OLLAMA=1 ではセットアップを呼ばず、拡張の取得・更新・アイコン生成が通ることを確認する。
- 公式取得失敗・起動待ち上限・pull 失敗では警告だけで、拡張インストールの終了コードが 0 となることを確認する。
- 実機での公式インストーラ実行・約 18.2 GB の既定モデルのダウンロードは、この自動検証では行わない。
